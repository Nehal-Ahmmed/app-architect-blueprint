🔄 1. UX EXTRACTION METHODOLOGY (FROM DESIGNS OR EXPLANATION)
--------------------------------------------------------------------------------

While the UI Plan defines *how things look and what components to build*,
the UX Plan defines *how things feel, behave, transition, and handle edge cases*:

1. Map User Journeys:
   • Trace the user's primary paths through the screens identified in the design.
   • E.g.: Onboarding -> Auth (Login/OTP) -> Home Dashboard -> Search/Filter ->
           Item Details -> Primary Action (Checkout/Save/Submit) -> Confirmation.

2. Interaction States (Every Screen Must Have All 4 States Defined):
   • Loading State   : Define skeleton shimmer loaders matching the card shapes in UI.
   • Empty State     : Define what shows when no data exists (e.g., empty cart, no
                       search results, no favorites) with a clear call-to-action.
   • Error State     : Define field error messages, network timeout banners, and
                       "Tap to Retry" button behavior.
   • Success / Normal: Standard populated screen.

3. Form Validation & Feedback UX:
   • Instant inline validation on blur or as user types (with debounce).
   • Disable primary CTA button during async network submission + show spinner.
   • Light haptic feedback on successful action or error shake on invalid input.

4. Navigation Transitions & Gestures:
   • Swipe-to-dismiss for modal bottom sheets and toast banners.
   • Shared element / Hero transition between list cards and detail views.
   • Android system back button hierarchy (sub-screen -> tab root -> home tab -> exit).

5. Permissions & Hardware UX:
   • Contextual rationale modal displayed before invoking system camera/location prompts.
   • Clear fallback path if user denies permission (e.g. manual address search).

6. Offline Usability UX:
   • Display subtle non-intrusive offline pill/banner when connection drops.
   • Render cached local database content instantly with a "Viewing cached data" tag.
